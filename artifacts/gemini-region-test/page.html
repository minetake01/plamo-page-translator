How regional failover works

When a primary region becomes unavailable, the control plane promotes a standby region and updates the global DNS record. This process usually completes in under sixty seconds.

The failover policy is defined in the routing policy and can be overridden per service. Use the failover_mode field to choose automatic or manual promotion.

Operators should monitor the replication lag before triggering a manual failover. A lag above five seconds can cause data loss for writes that have not replicated.

“A failover is not complete until the new primary has caught up with the replication log.”

For audit purposes, every promotion writes an event to the audit log with the actor, timestamp, and previous primary region.

You can also test the procedure in a staging environment before relying on it in production. The staging cluster mirrors the production topology but uses synthetic traffic.

Finally, review the post-incident report and update the runbook with any gaps discovered during the exercise.
